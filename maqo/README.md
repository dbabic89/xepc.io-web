# maqo.xepc.io

Cloudflare Worker `maqo-download`: the public download page and update manifest for Maqo.

- `GET /latest.json` — newest published version per platform (`android`, `macos`, `windows`), cached 10 min.
  A platform with nothing published is absent. Shape per key: `version`, `url`, `size`, `sha256`, `publishedAt`.
- `GET|HEAD /releases.json` — every published release, newest version first (then `desktop` before `android`), cached 10 min:
  `{"releases":[{"platform","version","publishedAt","notes","assets":[{"key","size","sha256"}]}]}`. `platform` is `desktop`
  or `android`; a desktop release lists its `macos` and `windows` assets in one entry; `notes` is the GitHub release body
  (empty string when none). Drafts, prereleases, tags that are not `desktop-vX.Y.Z` / `android-vX.Y.Z` and releases
  without an uploaded matching asset are left out. The GitHub list is read in pages of 100 (at most 10 pages).
- `GET|HEAD /download/{android|macos|windows}` — streams the current binary from the private releases repo;
  cached at the edge by asset id, so GitHub sees one download per new version. Unknown key: `404 {"error":"not_published"}`.
- `GET|HEAD /download/{android|macos|windows}/{version}` — the same for one exact version (`X.Y.Z`), file name
  `Maqo-X.Y.Z.<ext>`. Unknown key, malformed version or a version without that asset: `404 {"error":"not_published"}`.
- Everything else is the static page in `public/` (served through the `[assets]` binding).

The release repo is read with a fine-grained token; the token, the repo name and GitHub URLs never appear in
any response or log line. Tag/asset naming it relies on: `android-vX.Y.Z` (`Maqo-X.Y.Z.apk`) and
`desktop-vX.Y.Z` (`Maqo-X.Y.Z.dmg`, `Maqo-X.Y.Z.msi`).

This folder is not part of the main site: `build.sh` skips `maqo/`, and it deploys with its own `wrangler.toml`.

## Secret (once)

Create a fine-grained personal access token limited to the releases repo, permission Contents: read. Then:

```sh
cd maqo
npx wrangler login          # once per machine
npx wrangler secret put GITHUB_TOKEN
```

Paste the token at the prompt. It is stored in Cloudflare only, never in this repo.

## Deploy

```sh
cd maqo
npx wrangler deploy
```

`public/` must exist (the download page). The first deploy attaches the custom domain `maqo.xepc.io`
(`routes` with `custom_domain = true`); in the Cloudflare dashboard, check under Workers & Pages >
`maqo-download` > Settings > Domains & Routes that `maqo.xepc.io` is listed. The `xepc.io` zone must be in the
same Cloudflare account, and the domain must not already have a conflicting DNS record.

Logs: Workers & Pages > `maqo-download` > Logs (observability is on).

## Test

No dependencies, no build step:

```sh
cd maqo
node --test
```

## Store QR codes

`public/qr-android.svg` and `public/qr-ios.svg` are generated by `scripts/make-qr.sh`. Both point at a placeholder
URL until the Google Play and App Store listings exist: change the URLs in the script, run it, and update the
`href` of the `.pg-get a.qr` and `.pg-get a.store` links (the "Download" section; computers show the QR code above the store badge, phones only the badge) in `public/index.html`, `public/en/index.html` and `public/de/index.html`.
The store badges (`public/badge-google-play-{hr,en,de}.png`, `public/badge-app-store-{hr,en,de}.svg`) are the official
artwork from Google's badge page and Apple's Marketing Tools, with the Google PNG's transparent margin cropped. Both
brand guidelines forbid redrawing or recolouring them; keep them at least 40 px high.
iOS ships through the App Store only, so its hero card and its "Download" row are static (`data-static`) "Coming soon".
